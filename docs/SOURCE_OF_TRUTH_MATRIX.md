# Seramet Source Of Truth Matrix

This checkpoint records the intended authoritative owner for each transactional domain before external ERP/POS engines are connected. Existing UI screens remain the protected product interface; backend engines must sit behind stable NexusCore services.

| Domain                   | Authoritative Source                                                                        | Frontend Contract                              | External Engine Position                                                      | Notes                                                                                                                       |
| ------------------------ | ------------------------------------------------------------------------------------------- | ---------------------------------------------- | ----------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Orders                   | `TransactionRepository` and authoritative server database                                  | POS, Orders, Kitchen, Reports                  | External ERP adapters may receive normalized references                       | Commercial orders are never hard-deleted. Mutations require idempotency and expected revision.                              |
| Bills / Invoices         | Seramet transaction engine and authoritative server database                               | POS bill print, Invoices, Receivables, Finance | Accounting adapters consume mapped events                                     | Order, bill, invoice and receipt remain separate concepts.                                                                  |
| Payments                 | `PaymentService` backed by `PaymentIntent`, `PaymentRecord` and provider API endpoints      | POS payment modal, Receipts, Reconciliation    | M-Pesa Daraja, TendePay, card acquirers and banks are provider adapters       | Card and bank transfer remain separate backend payment types. Provider actions require idempotency keys.                    |
| Receipts                 | `ReceiptService` generated after confirmed payment                                          | Receipts, POS reprint, delivery actions        | Print/email/WhatsApp providers are delivery adapters                          | Receipts are immutable; reprints are logged.                                                                                |
| Reconciliation           | `ReconciliationService` with external transaction feed adapters and webhook ingestion       | Reconciliation, Finance, Daily Close           | TendePay, bank feeds, acquirers and M-Pesa feeds import external transactions | Matching does not create payment by itself. Provider webhooks are recorded before processing.                               |
| Accounting / GL          | `AccountingService` posts validated journal entries                                         | Finance, P&L, Balance Sheet, Cash Flow         | ERPNext is the leading candidate for mature GL once integrated                | Frontend calculations must not directly generate final GL without service validation.                                       |
| Inventory / Stock Ledger | `InventoryService` and stock ledger                                                         | Inventory, Recipes, Production, Wastage        | ERPNext stock ledger is a candidate                                           | Split/merge bills must not duplicate stock consumption.                                                                     |
| Customers                | `CustomerService`                                                                           | Customer 360, CRM, Loyalty, Complaints         | Frappe CRM may inform workflows                                               | Do not create a second customer master without mapping.                                                                     |
| Employees / HR           | `EmployeeService`                                                                           | People, Attendance, Schedule, Payroll          | HRMS is the leading candidate                                                 | Role and branch permissions drive UI access.                                                                                |
| Procurement / Payables   | `ProcurementService` and `PayablesService`                                                  | Procurement, Supplier Bills, Payables          | ERPNext supplier workflows are a candidate                                    | Supplier payment reconciliation connects to external transactions.                                                          |
| Print / Hardware         | `PrintService` / `SerametPrintService`                                                      | POS, Printers, Hardware Setup                  | Local print bridge is an adapter                                              | Branch hardware profiles determine KDS/printer behavior.                                                                    |
| Notifications / Delivery | `NotificationService`                                                                       | Reports, invoice delivery, alerts              | Email, WhatsApp and SMS providers are adapters                                | Delivery failures must not block sales.                                                                                     |

## Current Build Snapshot

- Safety branch pointer: `codex/pre-seramet-engine-integration`
- Current protected UI: TanStack Router/Vite React app using existing Seramet/NexusCore theme tokens and navigation.
- Current route coverage includes POS, Orders, Invoices, Receipts, Returns, Refunds, Finance, Expenses, Payables, Receivables, Reports, Audit Trail, Printer/Hardware setup and operational ERP modules.
- Current backend: `/api/seramet/*` routes use the authoritative PostgreSQL/D1-compatible repository selected by server configuration. Browser storage is a replaceable read cache, permitted offline command queue and device preference store only.
- Current auth model: production validates signed bearer identity against authoritative users, sessions, devices, roles, permissions and branch assignments. Development headers require explicit local development configuration and cannot start in production.
- Current provider model: M-Pesa Daraja STK and Dynamic QR adapters call Safaricom endpoints when credentials are configured. TendePay, bank-feed and card-acquirer ingress is handled through provider/webhook adapters and fails closed when required configuration or shared secrets are missing.

## Required Production Configuration

| Variable / Binding                                                                                                                              | Required For                 | Notes                                                                                                                   |
| ----------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `SERAMET_DB`                                                                                                                                    | Backend database persistence | Authoritative database binding. Production readiness fails when it is absent.                                           |
| `SERAMET_DATABASE_PROVIDER`                                                                                                                     | Database selection           | Production policy selects the configured PostgreSQL/Hyperdrive path.                                                    |
| `SERAMET_JWT_SECRET`, `SERAMET_JWT_ISSUER`, `SERAMET_JWT_AUDIENCE`                                                                             | Server-side auth             | JWT validation configuration; the secret must remain server-side and meet readiness rules.                              |
| `SERAMET_ENVIRONMENT`                                                                                                                           | Environment safety           | `development`, `test`, `staging` or `production`; unsafe development auth is rejected outside development.              |
| `SERAMET_MPESA_ENV`                                                                                                                             | M-Pesa                       | `sandbox` or `production`.                                                                                              |
| `SERAMET_MPESA_CONSUMER_KEY`, `SERAMET_MPESA_CONSUMER_SECRET`, `SERAMET_MPESA_SHORTCODE`, `SERAMET_MPESA_PASSKEY`, `SERAMET_MPESA_CALLBACK_URL` | M-Pesa STK                   | Required before live STK prompts are sent.                                                                              |
| `SERAMET_MPESA_QR_CPI`, `SERAMET_MPESA_QR_MERCHANT_NAME`                                                                                        | M-Pesa Dynamic QR            | Required before live QR generation is enabled.                                                                          |
| `SERAMET_MPESA_WEBHOOK_SECRET`                                                                                                                  | M-Pesa callback protection   | Optional shared secret accepted through callback query or `x-seramet-webhook-secret` where the provider supports it.    |
| `SERAMET_TENDEPAY_BASE_URL`, `SERAMET_TENDEPAY_API_KEY`, `SERAMET_TENDEPAY_WEBHOOK_SECRET`                                                      | TendePay                     | Live field mapping may need adjustment against the restaurant's official TendePay API contract.                         |
| `SERAMET_CARD_WEBHOOK_SECRET`, `SERAMET_BANK_WEBHOOK_SECRET`                                                                                    | Card and bank feed webhooks  | Required for webhook import endpoints to accept provider events securely.                                               |

## Integration Rule

External systems must be studied or connected behind adapters. Do not merge ERPNext, Odoo, NexoPOS, Dolibarr, Frappe CRM, HRMS or OSPOS into the Seramet frontend. Do not create competing ledgers.
